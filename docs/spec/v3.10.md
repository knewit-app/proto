# 기능명세서 v3.10 변경분

QA 관점 유즈케이스 점검 결과(UC-46~63)를 반영한다. 프로토타입은 `v/3.10.html`.

- 1: 프로토타입 버그. 명세는 그대로이고 화면을 명세에 맞췄다.
- 2: 화면에서 보이는 변경. 프로토타입과 기능명세서를 같이 고친다.
- 3: 서버 설계에만 해당한다. 기능명세서에만 반영한다.
- 4: 추가 유즈케이스 UC-46~63.

## 0. 기본안 (팀 확정 전)

프로토타입은 이 값들을 `POLICY` 상수 한곳에 모아 두었다. 명세의 비고에 "기본안, 팀 확정 전"을 적는다.

| 기준 | 값 | 기재할 행 |
| --- | --- | --- |
| '또 가고 싶나요?' 다시 묻는 간격 | `askAgainDays` = 30일 (마지막 답변 기준, '건너뛰기'도 답변으로 셈) | FN-SY-090 |
| '어제 간 곳' 하루 상한 | `ydMax` = 5곳. 그날 처음 고른 5곳으로 고정하고, 나머지는 다음 날로 | FN-SY-090 |
| 확인 대기 N일을 세는 기준 | 대기가 생긴 날부터 센다. 휴면 기간과 그 카드사의 사용자 멈춤 기간은 빼고 센다 (`pendingAgeExcl`) | FN-SY-080 |
| 장소당 유효 규칙 | 가장 최근 것 하나. 옮기기로 생긴 규칙은 다시 따라가지 않는다 | FN-SY-081 · FN-SE-121 |

### 기능명세서

| 행 ID | 바꿀 내용 |
| --- | --- |
| FN-ON-010 | **Apple 로그인은 시스템 시트(S-ONB-01a)를 거친다.**<br>- 처음 가입: 이름(편집 가능), 이메일 공유 · 가리기(기본: 공유), 'Face ID로 계속' · '암호로 계속'<br>- 기존 회원(로그아웃 · 로그인 만료 뒤): 'Face ID로 계속'만. 약관을 건너뛰고 원래 있던 곳으로 간다. 로그인 만료면 그 화면, 아니면 홈<br>- Apple은 이름 · 이메일을 **처음 가입할 때 한 번만** 준다. 서버가 그때 저장하고, 이후 로그인에는 식별자만 온다.<br>- 고른 이름은 프로필 이름과 아바타 이니셜(COM-12)의 기본값이다.<br>- 가린 이메일(`…@privaterelay.appleid.com`)로 메일을 보내려면 Apple 개인 이메일 릴레이에 발신 도메인을 등록해야 한다.<br>- 이 Face ID는 Apple 시트 안의 시스템 인증이다. 앱은 Face ID 권한(NSFaceIDUsageDescription)을 묻지 않고, 앱 잠금도 없다(D-18).<br>- 카카오 로그인도 같은 규칙: 기존 회원은 약관을 건너뛴다. |

### FN-ON-031 권한 상태별 동작

내 위치 버튼, 동네 선택의 '현재 위치', 설정 › 위치기반서비스, 설정 › 알림, S-ONB-05 '다 되면 알림 받기'가 모두 이 상태를 읽어 같은 규칙으로 움직인다.

| 권한 상태 | 위치 | 알림 |
| --- | --- | --- |
| 아직 안 물음 | iOS 위치 팝업을 띄운다(한 번 허용 / 앱을 사용하는 동안 허용 / 허용 안 함, '정확한 위치' 켬 · 끔). 허용하면 현재 위치, 거부하면 S-HOME-01a | iOS 알림 팝업을 띄운다(허용 안 함 / 허용) |
| 허용 | 현재 위치로 추천, 도보 시간 표시 | 바로 켬 |
| 거부 | 팝업이 다시 뜨지 않는다. 앱 시트 '설정에서 위치를 허용해 주세요 · 설정 열기' | 앱 시트 '설정에서 알림을 허용해 주세요 · 설정 열기'. 설정 화면에 '알림이 꺼져 있어요' 안내 |
| 한 번 허용 | 이번 실행 동안만 허용과 같다. 앱을 다시 열면 아직 안 물음으로 돌아간다 | — |
| 대략적 위치 | 동네 기준 추천, 도보 시간 대신 동네명, 헤더 '대략적인 위치로 찾았어요' (FN-SE-030) | — |

위치는 약관 동의가 먼저다. 약관이 없으면 iOS 상태와 관계없이 S-HOME-01b를 띄운다.
